# Common Resume Mistakes — What to Avoid

## Source: Harvard Career Services, r/EngineeringResumes, The Tech Resume Inside Out

---

## Harvard's Top 5 Resume Mistakes
1. Spelling and grammar errors
2. Missing email and phone information
3. Using passive language instead of action words
4. Not well organized, concise, or easy to skim
5. Not demonstrating results

---

## Formatting Mistakes

### Fatal Formatting Errors
| Mistake | Why It's Bad | Fix |
|---------|-------------|-----|
| Multi-column layout | ATS scrambles columns; harder to scan | Single column only |
| Graphics, icons, progress bars | ATS can't parse; wastes space | Remove all graphics |
| Tables for layout | Content order gets scrambled | Use tabs and spacing |
| Fancy/custom fonts | May not render; ATS may not parse | Calibri, Arial, or Garamond |
| Headers/footers with key info | Many ATS skip headers/footers | Put everything in body |
| Color-heavy design | Prints badly in B&W; distracts | Black text, minimal color |
| Name too large (20pt+) | Gets truncated on some screens/printers | 16pt max for name |
| Font too small (<10pt) | Unreadable for humans | 10.5pt minimum for body |
| Cramped margins (<0.6in) | Feels dense, hard to read | 0.75in recommended |
| Too much white space (>1in margins) | Wastes space, looks empty | 0.75in recommended |

### Spacing Mistakes
| Mistake | Fix |
|---------|-----|
| No space between sections | Add 10pt before section headings |
| No space between experience blocks | Add 7pt before each role |
| Wall of text (no line spacing) | Set 13pt line spacing |
| Inconsistent spacing | Use the same spacing pattern throughout |

## Content Mistakes

### The "Responsibility Resume" (Most Common Mistake)
Listing what your job was instead of what you accomplished:

**BAD:** "Responsible for maintaining database systems"
**GOOD:** "Optimized database queries by 30% through schema redesign, preventing server overloads across applications handling millions of daily requests"

### Missing Domain Context (Second Most Common)
Writing generic technical descriptions instead of industry-specific ones:

**BAD:** "Developed web applications using Laravel and PostgreSQL"
**GOOD:** "Developed a legal compliance platform for veterinary business registration, implementing validation workflows to verify regulatory requirements (RUT, tax ID, Colombian legal standards) before authorizing store openings"

### Other Content Anti-Patterns
| Mistake | Why | Fix |
|---------|-----|-----|
| Starting bullets with "Responsible for" | Passive, no achievement | Start with action verb |
| Using "I" or "my" | Not resume convention | Drop pronouns entirely |
| Listing technologies without context | Doesn't show what you DID | "Built X using Y for Z" |
| Same action verb repeated | Looks lazy, boring to scan | Vary verbs across bullets |
| Buzzwords without substance | "Synergized cross-functional paradigms" | Describe what actually happened |
| Subjective self-assessment | "Excellent communicator" | Show, don't tell — give examples |
| Listing every technology ever touched | Dilutes your actual strengths | Only list what you can discuss in interview |
| Including irrelevant early experience | Takes space from relevant content | Condense old roles to 1-2 bullets |

## Structural Mistakes

### Section Naming (per r/EngineeringResumes wiki)
| Section | Correct Name | WRONG Names |
|---------|-------------|-------------|
| Work | "Work Experience" or "Experience" | "Professional Experience", "Employment History", "Job History" |
| Skills | "Skills" | "Technical Skills", "Relevant Skills" |
| Projects | "Projects" | "Academic Projects", "Personal Projects", "Technical Projects" |
| Education | "Education" | "Academic Background" |

### Section Ordering
| Mistake | Fix |
|---------|-----|
| Education first (for experienced engineers) | Put experience first, education last |
| Skills buried at bottom | Skills at top for tech roles |
| No clear section headings | Use bold, larger headings with separators |
| Chronological (oldest first) | Always reverse chronological (newest first) |
| Including summary/profile | Don't include unless senior/staff or career change |

### Date Issues
| Mistake | Fix |
|---------|-----|
| Using hyphens (-) for date ranges | Use en dashes (–): "Mar 2022 – Present" |
| "Current" or "Now" for current role | Use "Present" |
| Missing dates | Always include end date (or Present) |
| Inconsistent format (some "Jan", some "January") | Pick one format and stick to it |
| Seasons/semesters ("Winter 2022") | Use months: "Jan 2022" |
| Abbreviated years ('23) | Full year: 2023 |
| Including education start dates | Only graduation date |

## Language Mistakes

### Words and Phrases to NEVER Use
- "Responsible for" → replace with specific action verb
- "Helped" → replace with "Collaborated on", "Contributed to", "Enabled"
- "Worked on" → replace with "Developed", "Built", "Implemented"
- "Utilized" → just say "Used" or better yet, describe the action
- "Various" / "Multiple" → be specific (name them or give a number)
- "Etc." → either list them or cut the sentence
- "Successfully" → redundant (you wouldn't list failures)
- "References available upon request" → waste of space, assumed
- "Dear Hiring Manager" → this goes in cover letters, not resumes

### Tense Consistency
- **Current role:** Present tense OR past tense (pick one, be consistent)
- **All past roles:** Past tense only
- **NEVER mix tenses within the same role**

## Mistakes Specific to Tech / Engineering Resumes

### Technology Listing Mistakes
| Mistake | Fix |
|---------|-----|
| "Proficient in Microsoft Office" | Remove — this is assumed in 2025 |
| Listing HTML/CSS as primary skills for a senior role | Move to frontend category, not headline |
| Rating skills with stars/bars/percentages | Never — subjective and meaningless |
| Listing technologies you used once in 2015 | Only list what you can discuss confidently |
| Not specifying cloud services | "AWS" → "AWS (S3, SES, SNS, Lambda)" |

### Project Section Mistakes
| Mistake | Fix |
|---------|-----|
| Including very old projects (pre-career) | Only if still relevant and impressive |
| Not including links (GitHub, demo) | Add links where possible |
| Describing projects without tech stack | Always mention technologies used |
| Academic projects listed like work experience | Clearly label as projects |

## Cultural / Regional Mistakes

### US / International Applications
- NO photo
- NO age, birthdate, gender, marital status, nationality
- NO physical address (city/state optional)
- Professional email only (no funny handles)

### LATAM / Spanish Applications
- Same rules as above generally apply
- Technical terms stay in English (backend, frontend, DevOps, SOLID, CQRS, etc.)
- Don't literally translate — adapt naturally
- RUT, cedula, DNI references are appropriate when describing systems that handle these

## The "Too Much Information" Trap

A resume is NOT a complete autobiography. It's a marketing document. Include only what's relevant to the roles you're targeting. When in doubt, ask: "Would this make a recruiter MORE likely to call me?" If no, cut it.

**Cut candidates:**
- High school education (if you have a university degree)
- Hobbies/interests (unless directly relevant — e.g., open source contributions)
- Soft skills section (show these through experience bullets instead)
- Objective/summary statement (controversial — some say include, Harvard/r/EngineeringResumes say skip for experienced engineers)
- Certifications that are expired or irrelevant
