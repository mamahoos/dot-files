# Bullet Writing Guide — XYZ/STAR Formula & Action Verbs

## Source: Harvard Career Services, Google XYZ Formula, r/EngineeringResumes, Columbia STAR Method

---

## The XYZ Formula (Google's Recommended Format)

**"Accomplished [X] as measured by [Y] by doing [Z]"**

This is the gold standard for resume bullets. Every bullet should ideally contain:
- **X** = The accomplishment (start with action verb)
- **Y** = Measurable result (metric, percentage, number, scale)
- **Z** = How you did it (technologies, methods, approach)

### Examples

**BAD (responsibility-based):**
> Responsible for developing web applications for the company

**GOOD (XYZ formula):**
> Developed fintech web applications for credit management and transaction processing using React and NestJS, serving 50K+ active users across multiple financial products

**BAD:**
> Worked on database optimization

**GOOD:**
> Optimized database queries by 30% through schema redesign and index optimization, preventing server overloads across high-traffic applications handling millions of daily requests

## The STAR Method (For Complex Accomplishments)

When a bullet needs more context, use STAR condensed into 1-2 lines:

- **S**ituation: The context or challenge
- **T**ask: Your responsibility
- **A**ction: What you specifically did
- **R**esult: The measurable outcome

**Example:**
> Refactored legacy monolithic systems (Situation) into modular micro-flow architectures (Action), improving code maintainability and enabling independent deployment (Result) by applying SOLID principles and advanced design patterns (How)

## Action Verbs — Use These, Not Those

### STRONG Verbs (Use These)

**Technical / Engineering:**
Analyzed, Architected, Automated, Built, Configured, Created, Debugged, Decreased, Deployed, Designed, Developed, Implemented, Improved, Integrated, Migrated, Optimized, Programmed, Published, Reduced, Refactored, Scaled, Standardized, Streamlined

**Leadership:**
Coordinated, Defined, Delegated, Directed, Established, Led, Managed, Mentored, Oversaw, Prioritized, Supervised

**Analysis / Problem-Solving:**
Assessed, Audited, Diagnosed, Evaluated, Identified, Investigated, Resolved, Tested, Troubleshot, Validated

**Communication / Collaboration:**
Consulted, Documented, Facilitated, Liaised, Presented, Translated (business-to-technical)

**Impact / Achievement:**
Accelerated, Achieved, Boosted, Decreased, Delivered, Eliminated, Exceeded, Expanded, Improved, Increased, Minimized, Reduced, Strengthened

### SUPERFLUOUS / AWKWARD Verbs (Avoid per r/EngineeringResumes)

The wiki explicitly flags these as unnecessarily complex or vague. While some appear in other sources as "good" verbs (e.g., Harvard lists "spearheaded"), the r/EngineeringResumes community recommends simpler, clearer alternatives:

amplified, conceptualized, crafted, elevated, employed, engaged, engineered, enhanced, ensured, fostered, headed, honed, innovated, mastered, orchestrated, perfected, pioneered, revolutionized, spearheaded, transformed

**Frequently misused:** leverage, enhance, utilize (see r/EngineeringResumes wiki for detailed explanations)

### WEAK Verbs (NEVER Use These)
| Weak Verb | Why It's Bad | Replace With |
|-----------|-------------|-------------|
| Responsible for | Passive, says nothing about achievement | [Specific verb]: Developed, Led, Managed |
| Helped | Diminishes your contribution | Collaborated on, Co-developed, Contributed to |
| Worked on | Vague, no action | Developed, Built, Implemented |
| Assisted | Sounds junior regardless of seniority | Supported, Enabled, Facilitated |
| Handled | Generic | Managed, Processed, Resolved |
| Utilized | Pretentious version of "used" | Used, Applied, Leveraged |
| Participated in | No ownership | Contributed to, Co-led |
| Was involved in | Maximum vagueness | [Describe what you actually did] |

### Spanish Action Verbs (Equivalents)

**Technical:** Arquitecte, Automatice, Construi, Configure, Depure, Desplegue, Disene, Desarrolle, Implemente, Integre, Migre, Optimice, Programe, Refactorice, Escale, Estandarice

**Leadership:** Coordine, Defini, Dirigi, Estableci, Lidere, Gestione, Supervise

**Impact:** Acelere, Logre, Incremente, Reduje, Mejore, Elimine, Fortaleci

## Quantification Strategies

### When You Have Hard Metrics
Use them directly:
- "Optimized queries by 30%"
- "Led teams of 4-6 engineers"
- "Handling millions of daily requests"
- "Serving 50K+ active users"
- "Reduced integration errors by 30%"
- "Delivered 10+ production deployments"

### When You Don't Have Exact Numbers
Use scale indicators:
- **Volume:** "millions of daily requests", "thousands of users", "dozens of integrations"
- **Team size:** "teams of 4-6", "cross-functional teams"
- **Scope:** "across 3 microservices", "12+ business modules", "multiple financial products"
- **Frequency:** "daily deployments", "weekly releases"
- **Business context:** "B2B and B2C channels", "enterprise clients", "multiple industries"

### What Counts as Quantification
Not just numbers — any concrete detail that shows scope:
- Technologies used (specific names, not categories)
- Types of systems (credit management, not just "web applications")
- Data sensitivity level (PII, financial data, legal documents)
- Industry domain (fintech, legaltech, logistics, security)
- Integration complexity (SAP, payment gateways, government APIs)

## Bullet Formatting Rules (per r/EngineeringResumes wiki)

- **Do NOT end bullet points with periods** — bullets are not sentences
- **1-2 lines long, aim for 1 sentence per bullet**
- **Use digits not spelled-out numbers:** 8, not "eight"; 30%, not "thirty percent"
- **No personal pronouns:** I, we, us, my, our, their
- **Don't spill onto next line with only 1-4 words** — extreme waste of space
- **Don't allow word wrapping with hyphens**
- **Avoid sub-bullets** — they clutter the resume
- **Avoid apostrophes, ampersands, and slashes** where possible
- **Avoid excessive adjectives/adverbs** (excellent, innovative, strategically, successfully, independently)
- **Order bullets from most relevant/impressive to least** within each role

## Bullet Length Guidelines

- **Ideal:** 1-2 lines (when printed/displayed)
- **Maximum:** 3 lines — if longer, split into two bullets
- **Minimum:** Don't make bullets so short they lose context

### Number of Bullets Per Role
| Role Recency | Bullets |
|---|---|
| Current role | 5-7 bullets |
| Previous role (1-3 years ago) | 4-6 bullets |
| Older roles (3-5 years ago) | 3-4 bullets |
| Old roles (5+ years ago) | 2-3 bullets |

### Priority of Bullet Content
For each role, prioritize bullets in this order:
1. **Domain-specific accomplishments** — what industry, what kind of system, what sensitive data
2. **Technical architecture decisions** — patterns, architecture, design choices
3. **Measurable impact** — metrics, scale, business results
4. **Leadership/collaboration** — team size, cross-functional work, client interaction
5. **Technology stack** — specific tools and versions (also in tech line)

## Domain Context — The Secret Weapon

**The single most impactful improvement you can make to any resume is adding domain context to every role.**

Generic bullet:
> Developed web applications using React and NestJS

Domain-rich bullet:
> Developed fintech web applications for credit management systems, card issuance and delivery, payment links, and transaction processing using React and NestJS, structured under Hexagonal Architecture and DDD

The domain context transforms a generic developer into a specialized professional with relevant industry experience. This is what makes companies say "this person understands our business."

### Domain Descriptors to Always Include
- **Fintech:** credit management, card issuance, payment processing, transaction systems, financial data
- **Legaltech:** document management, electronic signatures, compliance, legal processes, regulatory validation
- **Security:** surveillance systems, access control, ID verification, traceability, security monitoring
- **Logistics:** cargo tracking, inventory management, supply chain, dispatch, fleet management
- **Healthcare:** patient data, clinical systems, regulatory compliance (HIPAA)
- **E-commerce:** product catalogs, shopping carts, payment integration, order fulfillment
- **Construction/Industrial:** equipment tracking, hauling operations, driver hour logging, SAP integration

## Things to NEVER Include in Bullets

1. **Personal pronouns** — no I, my, we, our, me
2. **"Responsible for"** — passive, says nothing
3. **Narrative/paragraph style** — use bullets, not prose
4. **Subjective self-assessment** — no "excellent communicator", "fast learner", "passionate"
5. **Obvious skills** — no "proficient in Microsoft Office", "experienced with email"
6. **Salary information** — never
7. **Reasons for leaving** — never
8. **Negative language** — never mention failures, conflicts, firings
9. **Abbreviations without context** — spell out on first use, then abbreviate
10. **Buzzwords without substance** — "synergy", "paradigm shift", "leverage" without concrete meaning
